打开一个地址失败，可能发生在不同层。先看错误信息，再决定检查什么。

这篇示例使用 Linux、Python 3 和本机回环地址，不需要修改防火墙，也不向局域网开放端口。

## 先确认当前环境

在开始之前，确认当前系统、身份、路径和工具：

```sh
uname -s
id
pwd
command -v python3
command -v curl
command -v ss
```

如果 `uname -s` 不是 Linux，不要直接照搬后面的 `ss` 命令。工具不存在，也不代表网络坏了。

## 启动一个只在本机访问的服务

新建临时目录，避免把个人文件作为网页公开：

```sh
lab_dir=$(mktemp -d)
cd "$lab_dir"
printf '%s
' 'hello from a local lab' > index.html
python3 -m http.server 18080 --bind 127.0.0.1
```

服务会占用当前终端。保持它运行，在第二个终端检查：

```sh
ss -ltnp 'sport = :18080'
curl --noproxy '*' -i http://127.0.0.1:18080/
```

预期能看到监听端口，以及包含 `hello from a local lab` 的 HTTP 响应。实际结果需要你运行后确认。

## 两种错误，两个方向

保持服务运行，访问一个不存在的文件：

```sh
curl --noproxy '*' -i http://127.0.0.1:18080/missing-file
```

此时预期收到 HTTP 404。它说明已经连到 HTTP 服务，但请求的资源不存在。

回到第一个终端，按 `Ctrl+C` 停止服务，再运行：

```sh
curl --noproxy '*' -i http://127.0.0.1:18080/
ss -ltnp 'sport = :18080'
```

如果停止后没有其他进程监听该端口，连接通常会被拒绝。

| 现象 | 已经知道什么 | 下一步检查 |
| --- | --- | --- |
| Connection refused | 连接在 TCP 阶段未建立；不能仅据此断定原因 | 是否监听、监听地址、目标地址、拒绝规则 |
| HTTP 404 | 已经获得 HTTP 服务响应 | 请求路径、站点目录、路由 |
| 超时 | 请求没有在规定时间内完成 | 路径连通性、丢弃规则、服务响应等 |

## 从证据判断，不急着改配置

`Connection refused` 不能自动证明「防火墙有问题」，也不能自动证明「服务没启动」。没有监听是常见原因，主动拒绝规则也可能产生类似表现。

先确认实际目标与监听状态，再去读服务日志或检查其他层。不要因为浏览器显示失败，就先关防火墙。

## 自己再做一遍

关闭这篇文章，把端口改为 `18081`，独立重做。记录监听输出、成功响应、404 和停止服务后的现象，并解释每一种结果能证明什么。

完成后停止服务。临时目录只用于本次实验，可确认路径和内容后自行删除。
